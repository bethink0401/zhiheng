# 知衡真实数据开发与比赛演示隐私规则

| 项目 | 内容 |
| --- | --- |
| 文档版本 | V1.0 |
| 更新日期 | 2026-08-21 |
| 适用数据 | 项目发起人的 Apple Health/Apple Watch 数据、主观感受和生活事件 |
| 默认原则 | 本地优先、最少使用、明确授权、可撤回、演示脱敏 |

## 1. 使用目的

真实数据只用于：

- 验证 HealthKit 读取和数据质量。
- 选择符合事实的比赛故事。
- 验证个人基线、趋势和微计划评估。
- 在项目发起人明确同意后制作脱敏截图、录屏或报告。

不得用于广告、出售画像、公开数据集、基础模型训练或与本项目无关的研究。

## 2. 数据分级

### A 级：禁止进入仓库和技术日志

- 原始 HealthKit 样本。
- Apple Health 完整导出 XML/ZIP。
- 姓名、Apple ID、电话号码和地址。
- 设备序列号、UDID 和开发团队 ID。
- 完整 AI 健康对话。
- 精确症状自由文本。
- 带有真实身份和精确日期的截图或报告。

### B 级：仅在设备本地处理

- 每日睡眠、心率、HRV 和活动聚合值。
- 每日主观感受。
- 生活事件和备注。
- 微计划执行记录。
- 未脱敏的健康事实包。

### C 级：可进入项目文档或比赛材料

- 数据类型和有效天数。
- 百分比变化、范围或重新编号后的相对日期。
- 去除身份、精确日期和账户信息的图表。
- 明确标注的合成数据。
- 经项目发起人确认的脱敏结论。

## 3. 数据获取

- 优先通过知衡真机 App 的 HealthKit 只读授权获取。
- 每类权限单独说明用途，拒绝后仍提供降级体验。
- 不读取与第一版功能无关的数据类型。
- 不通过私有数据库、备份文件或未授权接口绕过 HealthKit。
- Apple Health 导出文件只有在用户主动放入指定临时位置时才处理。
- 原始导出不提交到仓库，处理结束后由用户决定保留或删除。

## 4. 开发存储

- 原始 HealthKit 数据默认保留在系统 HealthKit 中。
- App 本地只保存功能需要的聚合结果和用户主动记录。
- CareKitStore 保存微计划、任务、日程和 Outcome。
- SwiftData 保存主观记录、生活事件和分析摘要。
- 真实数据不得写入测试 Fixture；测试使用合成或充分脱敏数据。
- 仓库需要配置忽略规则，阻止常见健康导出、密钥和真实截图进入版本管理。

## 5. AI 使用

- 只发送完成回答所需的聚合健康事实包。
- 默认移除姓名、联系方式、设备标识和不必要的精确日期。
- 原始样本数组和完整用户备注不发送给模型。
- 请求前在产品中说明使用哪些数据类别。
- 正式服务通过后端代理，不在客户端保存正式 API Key。
- 后端默认不保留健康事实包；错误日志不能记录请求正文。

## 6. 截图、录屏与答辩

制作材料前检查：

- 隐藏姓名、头像、Apple ID 和通知内容。
- 隐藏或替换精确日期，优先使用“第 1 天～第 7 天”。
- 隐藏设备序列号、UDID、Team ID、API Key 和服务器地址中的敏感参数。
- 只展示支持比赛故事所需的指标。
- 模拟数据持续显示“演示数据”标识。
- 真实数据持续显示“本人授权的脱敏数据”或等价说明。
- 不展示可能识别第三方的信息，例如日历参与人和聊天内容。
- 录屏前开启合适的专注模式，避免私人通知弹出。

## 7. 使用他人数据

第一版默认只使用项目发起人本人的数据。需要邀请测试用户时：

- 先说明目的、读取范围、存储方式和退出方式。
- 不要求测试用户把 Apple Health 导出发送给团队。
- 优先让数据始终留在测试者设备上。
- 公开展示任何他人数据前取得单独、明确的展示同意。
- 不使用未成年人数据。
- 用户退出测试后删除项目持有的可识别记录。

## 8. 日志规则

开发日志可以记录：

- “睡眠有 72 个有效日”。
- “最近 7 天相对基线下降约 8%”。
- “HealthKit 查询返回部分授权”。

开发日志不能记录：

- 每天的完整健康数值序列。
- 精确症状描述。
- 账户、设备和证书标识。
- 完整事实包或模型请求正文。

必要调试使用合成数据重现。真实数据问题无法合成时，只记录最小现象和处理结果。

## 9. 数据删除与事故处理

用户删除数据时需要覆盖：

- SwiftData 中的主观记录和生活事件。
- CareKitStore 中属于知衡的计划和 Outcome。
- 本地 AI 对话记录。
- App 生成的缓存、导出报告和临时文件。

知衡不删除系统 Apple Health 中由其他 App 或设备生成的原始数据。

如果敏感数据误入仓库、日志或比赛材料：

1. 立即停止继续传播。
2. 不在新的日志中复制敏感内容。
3. 删除公开材料或限制访问。
4. 相关密钥立即轮换。
5. 评估版本历史和备份影响。
6. 记录不含敏感内容的事件原因、影响和修复。

## 10. 每次真实数据演示前检查

- [ ] 数据属于项目发起人本人，或已获得明确同意。
- [ ] 展示目的与第一版功能直接相关。
- [ ] 只包含最少必要指标。
- [ ] 姓名、账户和设备标识已移除。
- [ ] 精确日期已经隐藏或替换。
- [ ] 真实与模拟数据标签清楚。
- [ ] 没有把相关性写成因果关系。
- [ ] 没有诊断、处方或治疗承诺。
- [ ] 录屏通知已控制。
- [ ] 导出文件保存位置和删除方式明确。
