| 项目 | 内容 |

| 不适用范围 | AI 自由回答、急症安全文案、通知锁屏文案、微计划效果文案 |

## 1. 目的与放行边界

本清单用于确认洞察文案能够说明“发生了什么”，同时不把数值方向写成健康好坏，不把同期背景写成原因，不用数据否定感受，也不因缺失、来源变化或孤立日期制造焦虑。

S09-08 完成的是工程与产品侧的固定检查基线，不等于医学专业人士已经签字。正式公开发布前仍需医学专业人士审阅所有固定问句、非诊断边界和就医提示；若审阅提出修改，必须更新本清单、固定文案和自动测试。

## 2. 一票否决规则

任一用户可见洞察出现以下情况，本轮不放行：

- 直接判断用户健康或疾病，例如“你不健康”“你患有……”“AI 判断你得了……”。
- 把上升/下降直接写成变好、变差、改善、恶化、危险或医学异常。
- 把生活事件、感受或单项指标写成确定原因，例如“就是因为”“导致了”“证明了”。
- 保证效果或制造服从压力，例如“一定改善”“只要这样做就会改善”“必须立即处理”。
- 数据不足、读取失败或无记录时补 0、沿用旧值或生成强结论。
- 用设备记录否定主观感受，或要求用户先用数据证明自己的感受。
- 普通洞察使用急症口吻、警告红色或承诺持续监护。
- “忽略”暗示删除健康数据，“不再提醒”导致洞悉页内容不可见，或失败后显示操作已成功。

“不能用于诊断”“不会据此判断健康变差”等明确否定句属于安全边界，不能因为包含单个敏感词而被机械判为失败；审阅必须检查整句语义。

## 3. 分层文案检查

### 3.1 观察到的事实

- [ ] 只陈述本地程序已有的时间范围、指标、聚合值、相对个人基线的方向和三档趋势结果。
- [ ] 数值方向只写“上升/下降”，不解释成健康更好或更差。
- [ ] 一次只突出一个主要变化；稳定或证据不足时不拼接强结论。
- [ ] 未使用综合健康分、医学正常范围、疾病名称或诊断语气。

### 3.2 可能解释

- [ ] 生活事件只写“同期出现、可能相关”，并明确不代表因果。
- [ ] 没有结构化背景时明确“先不猜测原因”。
- [ ] 主观记录读取失败与“没有记录”分开处理，不用失败触发追问。
- [ ] 设备未见变化时明确不能否定用户感受。

### 3.3 不确定性

- [ ] 每张卡均有独立不确定性层，不能折叠进事实或建议后省略。
- [ ] 变化卡说明 7/28 天窗口、未佩戴/测量时间等可能影响，并明确非诊断、非因果。
- [ ] 证据不足卡说明缺失不按 0 处理，也不据此判断健康变差。

### 3.4 建议

- [ ] 只提供继续观察、照顾当下感受或低负担日常节奏，不自动创建计划。
- [ ] 不承诺改善、治疗或确定效果，不因单项变化要求立即调整计划。
- [ ] 稳定状态不额外增加行动负担；感受需照顾时以感受优先。

### 3.5 可选追问

- [ ] 单张卡最多一个问题，界面明确标为可选并允许稍后回答。
- [ ] 使用“是否有……变化”补背景，不用“为什么”“是什么导致”预设原因。
- [ ] 问题不包含诊断、危险、异常、必须或立即等施压词。
- [ ] 问句使用“身体感受”而非先把用户描述定性为疾病或异常。
- [ ] 未回答内容不进入事实、解释或建议。

### 3.6 数据依据与质量降级

- [ ] 显示实际使用的 7/28 天范围、有效日、中位数、门槛、同向日、来源和版本。
- [ ] 未授权、无记录、失败、窗口不足、来源冲突/变化、最近断档和不支持分别说明。
- [ ] 无数据不显示“中位数 0”或“0 步”；读取失败不使用旧值代替。
- [ ] 离群保护使用“孤立日期保护”，不把某天记录称为用户身体“异常”。
- [ ] 不显示 bundle identifier、设备序列、样本 ID、主观记录 ID 或自由文本。

### 3.7 用户控制

- [ ] 已读/未读只表示阅读状态，不表示健康状态发生变化。
- [ ] “忽略本期”明确只隐藏当前窗口卡片，并始终提供恢复入口。
- [ ] 同类提醒开关明确只影响未来低频提醒，不删除数据、不隐藏洞悉页内容。
- [ ] 读写失败保留正文和原状态，提供重试，不显示乐观成功。
- [ ] 真实与演示模式的状态和提示相互隔离。

## 4. 固定场景矩阵

| 编号 | 输入场景 | 必须出现 | 禁止出现 |
| --- | --- | --- | --- |
| COPY-01 | 质量合格的持续变化、无背景 | 7/28 天事实、个人基线、不确定性、一个可选背景问题 | 原因猜测、自动计划、健康好坏 |
| COPY-02 | 达到门槛的“值得继续观察” | 实际门槛、继续观察 | 升级为持续变化或危险 |
| COPY-03 | 变化与生活事件同期 | “同期”“可能相关”“不能确定原因” | “事件导致指标变化” |
| COPY-04 | 变化且已有感受 | 感受是背景、同时出现不代表因果 | 用指标解释或否定感受 |
| COPY-05 | 四项核心指标稳定但感受需照顾 | 感受值得重视、设备不能否定感受、最多一个问题 | “数据正常所以不用管” |
| COPY-06 | 完整稳定集且感受一般 | 未见明确变化、保持节奏、不增加负担 | “你很健康”、额外强制行动 |
| COPY-07 | 当前 7 天有效日不足 | 明确有效日不足、继续收集 | 0 值、强趋势 |
| COPY-08 | 28 天个人基线不足 | 明确基线不足 | 与人群正常值比较 |
| COPY-09 | 无可见数据 | 不补 0、未形成来源 | “活动为 0”“健康变差” |
| COPY-10 | 读取失败 | 本次读取失败、不用旧值或 0 代替 | 把失败写成没有记录 |
| COPY-11 | 来源冲突或变化 | 数据不可直接比较、不形成强结论 | 把断档写成身体变化 |
| COPY-12 | 最近完整日断档 | 暂不形成趋势 | 推断未佩戴或恶化 |
| COPY-13 | 孤立日期被保护 | 孤立日期不参与本次结论、原记录保留 | “异常身体状态” |
| COPY-14 | 主观记录读取失败 | 暂时无法读取、不追问、不猜测 | 当作没有背景 |
| COPY-15 | 演示模式 | 明确演示、不读取真实感受 | 冒充真实健康结论 |
| COPY-16 | 已读/未读切换 | 仅阅读状态变化 | 结论或健康状态变化 |
| COPY-17 | 忽略并恢复 | 只隐藏本期、数据未删除 | 永久删除或不可恢复 |
| COPY-18 | 关闭并恢复同类提醒 | 只控制未来低频提醒、洞悉页仍可查看 | 关闭全部洞察或删除数据 |

## 5. 自动与人工验证

`InsightTests` 固定执行以下自动检查：

- 变化、同期事件、稳定、主客观不一致、不可用、孤立日期和演示分支都保留四层结构。
- 用户可见文案不包含固定诊断、恐吓、伪因果和效果保证断言。
- 三类追问使用中性“是否”问句，不预设原因，不包含施压词。
- 上升/下降事实不映射为健康变好/变差。
- 所有不可用原因均不生成强结论，不伪造 0。
- 孤立日期使用中性保护文案，不称为身体异常。

自动检查不能代替语境审阅。每次修改固定洞察文案后，产品审阅者还要逐项阅读 COPY-01～COPY-18；修改疾病、症状、就医或安全提示时，必须重新取得医学专业审阅。
