# 知衡每日开发日志

本目录按自然日保存项目开发记录，时区固定为 Asia/Shanghai。

## 文件命名

每天第一次进行实质性开发、设计、测试或项目决策时，创建：

```text
开发日志/YYYY-MM-DD.md
```

同一天的后续工作继续追加到当天文件，不重复创建文件。没有任何项目工作的日期不生成空日志。

## 自动记录规则

“自动记录”由项目代理工作流保证：

1. 开始任务前检查当天日志是否存在。
2. 不存在时创建当天日志并填写今日目标。
3. 每完成一个独立任务，立即在“已完成事项”追加记录。
4. 测试失败、任务阻塞和决策变化同样必须记录。
5. 工作结束前更新“待办事项”和“下一步唯一任务”。
6. 最终回复用户之前检查当天日志已经更新。

开发日志不能依靠模型回忆补写，也不安排无开发内容的定时空记录。

## 每日日志结构

```markdown
# YYYY-MM-DD 开发日志

## 今日目标

- 目标和任务编号。

## 已完成事项

### HH:MM｜任务编号｜标题

- 完成内容：
- 修改文件：
- 验证结果：
- 关键决定：

## 待办事项

- [ ] 尚未完成的具体事项。

## 问题与风险

- 问题、影响和处理方式。

## 下一步唯一任务

- 任务编号和可以直接执行的动作。
```

## 内容要求

- 使用可以验证的事实，不写“做了一些优化”“基本完成”。
- 必须写修改文件和验证结果。
- 不记录 API Key、用户身份、原始健康数据或完整敏感对话。
- 真实数据只描述数据类型、覆盖情况和脱敏后的结论。
- 失败结果不能删除；修复后新增后续记录。
- 当天日志原则上只追加，不重写已经发生的事实。

## 历史说明

每日独立日志制度建立前的记录保存在 `docs/development-log.md`。该文件作为历史归档保留，不再作为新日志的主要入口。
