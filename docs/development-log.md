# 知衡开发日志

> 历史归档说明：自 2026-08-21 起，新的开发记录改为保存在 `开发日志/YYYY-MM-DD.md`。本文件保留此前记录，原则上不再追加。日志规则见 `开发日志/README.md`。

本文件曾用于记录项目早期进展。历史记录原则上不删除；如果早期决定之后发生变化，以新的每日开发日志和当前标准文档为准。

## 日志填写模板

复制下面的模板，填好后插入到“日志记录”标题下方：

```markdown
### YYYY-MM-DD｜任务编号｜简短标题

**状态：** 已完成 / 进行中 / 阻塞 / 决策变更

**本次目标**

- 本次要解决的问题。

**完成内容**

- 实际完成的工作。

**修改文件**

- `文件路径`：修改说明。

**验证**

- 执行的测试、检查或人工验证。
- 结果：通过 / 未通过 / 部分通过。

**关键决定**

- 决定、原因和影响；没有则写“无”。

**已知问题与风险**

- 尚未解决的问题；没有则写“无”。

**下一步**

- 下一项唯一、具体、可执行的任务编号和内容。
```

## 日志规则

1. 每完成一个可验收任务必须记录。
2. 没有验证和日志的任务不能标记为完成。
3. 记录事实，不用“优化了一些”“基本完成”等无法验证的表述。
4. 必须列出修改文件，方便以后追查。
5. 测试失败也必须记录，不能只记录成功。
6. 不在日志中写入 API Key、用户身份、原始健康数据或完整敏感对话。
7. 下一步只写最优先的一项，避免同时开启过多工作。
