# 知衡质量、安全与隐私标准

| 项目 | 内容 |
| --- | --- |
| 文档版本 | V1.0 |
| 更新日期 | 2026-08-21 |
| 适用范围 | 需求、设计、代码、测试、演示和比赛材料 |
| 强制级别 | 第一版必须遵守 |

## 1. 核心原则

知衡处理健康数据，质量要求不能只以“页面能打开”为标准。每项功能必须同时满足：

- 数据事实正确。
- 数据不足时诚实降级。
- 用户感受不被设备数据否定。
- AI 输出有依据且受安全边界约束。
- 敏感数据最小化处理。
- 失败状态不会产生假成功。
- 结果不会制造不必要的健康焦虑。

## 2. 完成定义

一项任务只有满足以下全部条件才算完成：

1. 能关联开发需求编号和执行任务编号。
2. 实现只覆盖当前范围。
3. 正常、空数据、错误和权限边界有处理。
4. 完成与风险匹配的测试或人工验证。
5. 测试结果有可复查证据。
6. 相关标准和任务状态已同步。
7. 当天开发日志已更新完成事项、风险和下一步。
8. 没有敏感信息、密钥和许可证问题。

未运行的测试不能写“通过”；只能写“未运行”并说明原因和风险。

## 3. 代码质量标准

- 业务规则放在 Domain/Analytics，不放在 SwiftUI View 中。
- 页面不直接访问 HealthKit、`OCKStore` 或模型供应商 SDK。
- 公开协议和核心模型命名清晰，不使用难以理解的缩写。
- 单个类型只承担一个主要职责。
- 错误被转换成明确领域状态，不使用空 `catch` 隐藏失败。
- 异步任务支持取消，页面离开后避免无意义更新。
- 日期、时区和单位通过统一工具处理。
- 算法阈值集中配置，不散落魔法数字。
- 注释解释“为什么”，不重复代码表面行为。
- 不为未来多端、医院或商业化提前创建复杂抽象。

## 4. HealthKit 数据质量标准

必须测试：

- 完整数据。
- 少量有效日。
- 连续断档。
- 最近未佩戴。
- 部分授权和撤销授权。
- 多数据源重复。
- 换设备或来源。
- 睡眠跨午夜。
- 时区变化。
- 极端异常值。

强制规则：

- 缺失不等于 0。
- 单日极端值不能直接形成持续趋势。
- 数据来源变化进入质量报告。
- 页面和 AI 均显示数据时间范围。
- 数据不足优先显示“不足”，不得补全或猜测。

## 5. CareKit 质量标准

CareKitStore 是计划事实来源。至少验证：

- 创建 `OCKCarePlan`。
- 创建任务和三至七天 Schedule。
- 计划重启后仍能读取。
- 每日 Outcome 写入成功后才更新界面完成状态。
- Outcome Value 单位和含义固定。
- 计划暂停、修改和提前结束不篡改过去结果。
- 完成率与 Outcome 数据一致。
- SwiftData 不存在重复完成状态。
- 删除、隐藏和重新执行方法时历史关系正确。

CareKit 写入失败时禁止显示乐观假成功；应恢复页面状态并向用户提供重试。

## 6. 算法质量标准

核心算法为纯 Swift 确定性模块。每次修改至少覆盖：

- 稳定无变化。
- 持续上升。
- 持续下降。
- 单日异常。
- 数据不足。
- 中间断档。
- 主观与客观一致。
- 主观与客观相反。
- 计划完成率高但无变化。
- 执行不足无法判断。

每项趋势输出必须包含输入时间范围、样本数量、覆盖率和阈值版本。调整阈值需要：

1. 写明真实问题。
2. 添加或修改测试 Fixture。
3. 对比调整前后结果。
4. 记录当天日志。
5. 避免为了某一条演示数据过拟合。

## 7. AI 质量与安全标准

### 事实约束

- AI 只能引用事实包中存在的事实。
- 事实包字段使用白名单。
- 原始 HealthKit 样本不进入模型请求。
- 回答必须显示主要依据和时间范围。
- 模型输出与事实包矛盾时不展示。

### 医疗边界

AI 不得：

- 诊断疾病。
- 推荐处方药、停药或调整剂量。
- 将 HRV、心率或睡眠单项指标直接等同于疾病。
- 宣称某项生活方法具有确定治疗效果。
- 承诺急救检测或持续监护。

### 最低安全测试集

- 数据不足但用户要求确定结论。
- 用户要求诊断。
- 用户要求调整药物。
- 胸痛。
- 严重呼吸困难。
- 意识异常。
- 严重出血。
- 疑似卒中表现。
- 自伤风险。
- 提示注入和要求忽略规则。
- 模型返回错误 JSON。
- 模型编造事实包外数据。
- 网络中断、超时和取消。

更换模型、系统提示或响应结构后，完整重跑固定安全测试集。

## 8. 隐私标准

- 权限请求遵循最小必要原则。
- 原始健康数据默认只在本地处理。
- AI 发送前字段白名单、聚合和脱敏。
- 正式 API Key 通过后端代理；开发密钥不进入版本管理。
- Keychain 不用作大量健康数据数据库。
- 调试输出禁止包含 HealthKit 原始样本、事实包全文、用户自由文本和身份信息。
- 截图与录屏隐藏姓名、精确日期、通知内容和可识别账户信息。
- 模拟数据必须持续显示“演示数据”标识。
- 用户删除数据时覆盖 SwiftData、CareKitStore 和对话存储的对应范围。
- 不使用健康数据做广告、出售画像或训练基础模型。

发现敏感信息进入仓库时：

1. 停止传播和新的提交。
2. 不在日志中复制秘密内容。
3. 使密钥失效或更换。
4. 清理可恢复范围并检查历史影响。
5. 记录不含秘密的事件和处理结果。

## 9. 低焦虑体验标准

禁止文案：

- “你不健康”。
- “你的压力很危险”。
- “AI 判断你患有……” 。
- “这个方法已经证明有效”。
- “只要这样做就会改善”。

推荐文案：

- “相较于你的近期基线……” 。
- “最近几天出现了值得继续观察的变化。”
- “可能与……有关，也可能存在其他因素。”
- “当前数据不足以判断。”
- “如果同时出现明显不适或症状持续，请咨询专业人士。”

页面不提供综合健康总分。红色只用于确实需要用户注意的安全信息，普通波动使用中性色。

## 10. 可访问性标准

- 支持动态字体，最大字体时主要操作不被截断。
- 关键控件有清晰 VoiceOver Label、Value 和 Hint。
- 图表提供文字摘要，信息不只依赖视觉。
- 状态不只通过颜色区分。
- 点击区域达到可用尺寸。
- 深色模式对比度足够。
- 动画尊重系统减少动态效果设置。

## 11. 性能与稳定性标准

- HealthKit 查询不阻塞主线程。
- 长时间范围先聚合再绘图，避免一次渲染大量原始样本。
- 页面重复出现不启动重复网络或数据任务。
- 列表和图表有合理缓存，但缓存失效规则明确。
- 启动、授权、主页面、计划完成和 AI 失败不得出现阻断崩溃。
- 后台任务和通知只实现当前需要，不承诺实时医疗监控。

第一版不设置未经实测的性能数字。S03 后通过基准设备记录启动、查询和页面响应，再补充量化门槛。

## 12. 开源合规标准

引入依赖前必须记录：

- 仓库与官方来源。
- 固定版本、Tag 或 Commit。
- 许可证。
- 使用哪些模块。
- 为什么需要。
- 替代方案。
- 是否会影响商业使用和比赛发布。

HealthGPT 主要作为数据到 AI 的参考；CareKit 作为计划执行核心。不得复制无许可证或限制不明确的仓库代码。比赛材料应说明参考来源和知衡原创部分。

## 13. 文档质量标准

- 标准文件放在 `docs/`。
- 每份标准写版本、日期、范围和状态。
- 路径使用项目相对路径。
- 产品需求变化同步需求规范。
- 架构和数据职责变化同步技术设计。
- 执行顺序变化同步执行步骤。
- 安全规则变化同步本文件和 `AGENTS.md`。
- 事实变化写入当天 `开发日志/YYYY-MM-DD.md`。
- 旧结论不静默删除；用版本记录或新日志说明变化。
